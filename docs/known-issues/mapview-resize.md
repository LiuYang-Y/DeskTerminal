# 已知问题：地图跨尺寸重挂后右侧纯黑（GL 视口停在旧尺寸）

| 项 | 值 |
| --- | --- |
| 状态 | **搁置 / 未解决**（试修在 `wip/mapview-resize`，未定论，勿合 master） |
| 发现 | 2026-10-13，小米 M2102K1C（Android 11 / API 30 / 3200×1440@560dpi） |
| 影响面 | 首页地图卡 ↔ 全屏地图页 共用同一个 `MapView` 的所有切换 |
| 何时再处理 | **窄屏手机（PKR110）接上之后** —— 它的卡片/全屏尺寸差值不同，是天然对照组 |
| 证据 | `.verify/reg/mapview-resize-log.txt`（真机 `files/map/map.log` 的落盘副本，日志有轮转，别隔太久再取） |

## 现象

从首页点进全屏地图页：

* View 的 **layout 尺寸确实变了**（uiautomator 实测 2332×1264，布局没问题）；
* 但**画面只画满左边约 409dp，右边约 257dp 是纯黑** —— 不是页面底色，是什么都没画；
* 手动走一次 `onPause → onResume`（息屏再唤醒）之后，渲染宽度立刻变成 2331px，**黑条消失**。

## 日志对照（1433 → 2331）

`grep "before=" .verify/reg/mapview-resize-log.txt` 里最典型的一行：

```
15:13:06.507 I host: resumed after attach (refs=1 size=2331x1264 before=1433x1096 resized=true parent=ViewFactoryHolder)
```

* `before=1433x1096`：摘下来之前的尺寸，1433px ÷ 3.5 = **409.4dp** ＝ 首页地图卡；
* `size=2331x1264`：重挂之后的尺寸，2331px ÷ 3.5 = **666dp** ＝ 全屏地图页；
* `resized=true`：这次重挂确实跨了尺寸。

同一份日志里还有其它尺寸的样本（部分是步骤 6 用 `wm size` 模拟的屏幕，一并留作对照）：

```
15:12:05.467 size=2716x1440 before=1689x1272   （侧栏占位变化后的同一路径）
15:14:03.187 size=1555x900  before=915x732     （wm size 模拟的窄屏）
16:49:39.294 size=1689x1272 before=1689x1272 resized=false （同尺寸重挂，对照组：不跨尺寸就不该黑）
```

**结论：黑条只出现在 `resized=true` 的路径上，同尺寸重挂（`resized=false`）从不出现** ——
现象与"视口没跟着尺寸变"是自洽的。

## 根因（推断，未证实）

地图的 GL surface **按建 surface 那次的尺寸分配渲染视口**，之后 View 变大它不会自己跟着变。
而这条路径上 `refCount` 从 2 降到 1（新使用点先 `acquire`、旧的后 `release`），
**压根没走 `onPause`**，只有 `onResume` —— 视口就这么留在了旧尺寸上。

> 注意"推断"二字：唯一的强证据是**手动 pause/resume 之后黑条消失**，
> 这只能说明"重走一次 pause→resume 能修好"，不能证明"视口没重建"就是唯一原因。

## 试修与结果（在 `wip/mapview-resize` 上）

改法：重挂前后尺寸不同就补一次 `onPause`，隔 300ms 再 `onResume`。

* 同帧 / 隔一帧 `onResume` 实测**都不生效**（还是 409dp）→ 必须留延时，取 300ms；
* **6 次实测只有 1 次生效**，另外 5 次右侧仍是黑的。

也就是说"补 pause"很可能是**碰巧撞上了某次异步时序**，而不是真正的根因。
这正是它没进 master 的原因：一个不确定的时序补丁比一个已知缺陷更难维护 ——
后者至少能在窄屏机上被复现和推翻。

## 备选方案（窄屏机接上后按顺序试）

1. **尺寸变化时重建实例**（最笨但最可证伪）
   放弃"同一实例跨尺寸复用"，改成**按 (宽, 高) 缓存实例**：尺寸变了就 `onDestroy` 旧的、新建一个。
   代价：瓦片重下、镜头要重新种一次（但 `cameraSeeded` 已在宿主上，可以只种一次视角）。
   判据：新建实例后右侧是否还是黑的 —— 如果是，说明问题不在"重挂"而在布局本身。

2. **`TextureMapView`**
   换成纹理路径，渲染跟着 View 一起走合成，理论上没有独立 GL 图层的视口问题。
   代价：纹理路径要走 `dispatchDraw`，帧率通常不如 SurfaceView；而且本项目已经在用
   `DeskGlass` 兜底（见 `core/ui/DeskGlass.kt`），模糊方案不受影响。
   风险：需要重测首页卡 + 全屏页的帧率与拖动跟手度。

3. **问高德**
   黑条只出现在这条"跨尺寸复用"路径上，属于 SDK 内部行为；如果有官方开关或已知 issue，
   比我们自己猜时序划算。

## 复现步骤（窄屏机接上后照做）

1. 装 debug 包，`adb exec-out run-as com.qingke.desk cat files/map/map.log` 确认日志通；
2. 首页 → 点地图卡进全屏页，截图，量右侧黑条的像素宽度；
3. 息屏再唤醒（手动 pause/resume），再截图 —— 黑条消失即复现成功；
4. 逐个试上面的备选方案，每次都用"黑条宽度"这个量做判据，不要靠"看起来好了"。
