# 已解决：地图跨尺寸重挂后右侧纯黑（GL 视口停在旧尺寸）

| 项 | 值 |
| --- | --- |
| 状态 | ✅ **已解决**（2026-10-14，一加 PKR110 上验证通过） |
| 修法 | 地图容器改用 `TextureMapView`（纹理路径），见 `map/.../AMapSurface.kt` |
| 发现 | 2026-10-13，小米 M2102K1C（Android 11 / API 30 / 3200×1440@560dpi） |
| 复现 | 2026-10-14，一加 PKR110（Android 16 / API 36 / 1264×2780@560dpi）—— 同一现象，断崖列 1881px ↔ 1883px |
| 影响面 | 首页地图卡 ↔ 全屏地图页 共用同一块地图的所有切换（含导航） |
| 证据 | `.verify/fix-*.png`、`.verify/cycle-*.png`、`.verify/nav-*.png`（2026-10-14 一加实测） |

## 现象

从首页点进全屏地图页：

* View 的 **layout 尺寸确实变了**（一加上 uiautomator 实测 2332×1264，布局没问题）；
* 但**画面只画到 x=1883px，右侧 897px 是纯黑** —— 不是页面底色，是什么都没画；
* 手动走一次 `onPause → onResume`（息屏再唤醒）之后渲染宽度立刻变成 2331px，**黑条消失**。

## 根因（已定量证实，不再只是推断）

地图的 GL surface **按建 surface 那次的尺寸分配渲染视口**，之后 View 变大它不会自己跟着变。

一加上把这条从"推断"做成了"定量"：

```
侧栏宽度                 = 450px
画面起点                 = 1883px
1883 − 450               = 1433px
日志里首页卡的实际尺寸     = 1431×1096（同一份日志的 resumed after attach 行）
```

**1433 ≈ 1431** —— 视口**精确地**停在首页卡的宽度上，一个像素不差。

**为什么是单向下黑**：全屏(2332) → 首页(1431) 时，旧视口比新容器**宽**，
多出来的部分被 View 边界裁掉了，看不出来。所以只有"小 → 大"会暴露。

**为什么只有跨尺寸才黑**：`resized=false`（同尺寸重挂）时视口本来就是对的。

## 试过但放弃的方案：重挂时补一次 `onPause`

`wip/mapview-resize` 上的改法是：重挂前后尺寸不同 → 补一次 `onPause` → 隔 300ms `onResume`。

* 同帧 / 隔一帧 `onResume` 实测**都不生效**（还是 409dp 视口）；
* **6 次实测只有 1 次生效**，另外 5 次右侧仍是黑的。

**为什么放弃**：`MapView.onPause()` 只是让高德**停渲染线程**，并不**销毁 surface** ——
真正销毁 surface 的是 View 从窗口树彻底移除。所以这条路是在赌"某次异步时序刚好撞上"
（息屏唤醒之所以有效，是因为那会让窗口 relayout、SurfaceView 真的重建 surface），
**不是根因**。一个 1/6 成功率的时序补丁比一个已知缺陷更难维护。

## 最终方案：换纹理路径

`TextureMapView` 走 `TextureView`：内容画在**普通 View 的纹理**上，View 尺寸一变，
系统必然要求重绘 —— **从机制上绕开"视口不更新"**，不依赖任何时序。

落地形态：新增 `map/.../AMapSurface.kt`，把 `MapView` / `TextureMapView` 的差异包起来
（两者 `都 extends FrameLayout implements BaseMapView`，公开 API 同名同形，
但没有共同的父类型可以当变量类型 —— `BaseMapView` 只声明了 `loadWorldVectorMap`）。
默认走纹理版；保留 `USE_TEXTURE_MAP_VIEW` 常量是为了能在真机上改一个布尔值做 A/B 对照。

**代价**：失去 SurfaceView 的独立图层。本项目为零 —— 地图浮层做真背景模糊**本来就不行**
（见 `core/ui/DeskGlass.kt`），没有可失去的东西。

## 残留与后续

* **帧率未重测**：纹理路径要走 `dispatchDraw`，理论上比 SurfaceView 差。
  首页卡 15fps / 全屏页 30fps 的设置没变，真机上手拖动**跟手**（第 4 条），
  但没有做帧率级对比。如果以后发现长按拖动掉帧，这里是第一个要查的地方。
* **`wip/mapview-resize` 分支可删**：那条时序试修已被本方案取代。
* 本文保留诊断过程 —— 它记录了一个**通用教训**：GL 视口的尺寸问题不要用 pause/resume 去赌，
  要从"谁在分配 buffer"这一层换掉机制。
